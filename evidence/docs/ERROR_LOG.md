# 错误记录

## 2026-09-09 06:36 PDT - 绿色阶段共享航点未纳入锁定范围

- 现象：绿色专用的抓取和释放点已将 `joint4_to_joint3`、`joint6_to_joint5` 设为零，但绿色流程中复用的 `First` 与最终 `initial` 航点没有被执行层的名称白名单覆盖，容易让人误以为两个自由度没有受到完整流程保护。
- 根因：锁定规则按单个航点名称判断，而不是按“绿色流程已经开始”的状态判断。
- 处理：播放器改为从 `above_green_1` 起，到绿色流程结束的每个控制命令均强制两个关节为零；释放高度保持已验证的约 14 cm，并仍从末端当前位置垂直下落。
- 教训：用户定义的是一段运动的约束时，应以流程状态覆盖共享航点，而不能只枚举专用航点名。

## 2026-09-09 06:32 PDT - 绿色释放阶段遗漏关节锁定

- 现象：绿色抓取航点已锁定 `joint4_to_joint3` 与 `joint6_to_joint5`，但 `release_4`、`release_5` 仍沿用了非零的旧释放姿态，因此释放过程中两关节发生转动。
- 根因：将“抓取过程”错误地只理解为接近和闭合，没有把搬运、释放及回撤作为同一受限流程处理。
- 处理：两个绿色释放航点改为第 4、6 关节均为 `0` 的高位姿态；自动播放器增加绿色流程保护，即使 JSON 中误填非零值也会强制发布零值；Gazebo GUI 实测两物体在绿色垫上方约 14 cm 释放后垂直落下。
- 教训：涉及用户明确限制的关节，必须在数据层和执行层同时约束，并覆盖全过程航点验证。

## 2026-09-09 06:10 PDT - 绿色网格与零旋转抓取校准

- 现象：绿色物体原先位于第三列，绿色垫偏离红蓝垫所在排；将 `joint4_to_joint3`、`joint6_to_joint5` 置零后，第二个绿色点的初始航点误差约 4.4 cm。
- 根因：原绿色布局不是红蓝物体网格的延伸；末端两个旋转自由度锁零后，第三列位置超出该姿态的理想可达范围。
- 处理：绿色物体调整到第三行左右两个网格位置 `(0.24,0.24)`、`(0.30,0.24)`；绿色垫调整到与红蓝垫同排、同尺寸的 `(0.38,-0.12)`；绿色抓取航点第 4、6 关节固定为 `0`；抓取判定容差由 3.5 cm 增至 5 cm，并通过 Gazebo GUI 相机截图和 34 步自动序列验证。
- 教训：网格布局和末端姿态约束必须联合校准，不能只按单独坐标修改；修改后必须用 Gazebo 实际状态和画面复核。

## 2026-08-31 18:29 PDT - Gazebo 夹持插件未找到末端链接

- 现象：`gazebo_ros_vacuum_gripper` 报错 `Link [gripper_base] not found`，夹持服务未创建。
- 根因：Gazebo Classic 默认会合并固定关节两侧的链接，`gripper_base` 被合并到上游链接。
- 教训：向固定关节下游链接挂载 Gazebo 插件时，必须先设置 `preserveFixedJoint` 或在运行时确认链接已实际存在。
- 处理：为 `joint6output_to_gripper_base` 加入 `<preserveFixedJoint>true</preserveFixedJoint>` 后重新构建和验证。
